## 目标
1. 在 `Sidebar.vue` 的 `MemoryInfo` 上方新增「下载状态」组件，仅在**有下载任务时**显示。
2. 把系统默认下载器（Electron `DownloadItem` 兜底路径）从「无跟踪的落盘」改成「**后台跟踪的下载任务**」，与 aria2 一样可在下载列表查看进度/速度/状态。
3. 新组件展示：正在下载/待下载/失败 数量、当前传输速度、总体下载百分比。

## 核心问题（已确认）
当前系统下载器路径（`events.ts` 的 `fallbackToSystem`）只调用 `item.setSavePath(...)` 然后放任 Chromium 在后台落盘——**完全没有任务跟踪**，blob/data/空 URL 的下载在侧边栏/下载页里都不存在。需新建一套系统下载跟踪服务，让 aria2 与系统下载器共享统一的任务模型。

## 实现方案

### 文件 1（新建）：`electron/services/system-downloads.ts` —— 系统下载跟踪服务
内存级任务管理器（不持久化，符合「会话内后台下载」语义）。

- `interface SystemDownloadTask`：字段对齐现有 `DownloadTask`（`gid`/`url`/`filename`/`status`/`totalLength`/`completedLength`/`downloadSpeed`/`progress`/`dir`/`errorMessage`），`gid` 用 `sys_` 前缀 + 自增 id 与 aria2 的 gid 区分。
- `trackDownload(item: Electron.DownloadItem)`：在 `will-download` 触发时调用，注册 `item` 的 `updated`/`done` 事件监听，把进度（`getReceivedBytes`/`getTotalBytes`/状态）写入任务，并**节流广播**事件到渲染进程。
- `getTasks()` / `removeTask(gid)` / `clear()`：查询与清理接口。
- 事件广播：`BrowserWindow.getAllWindows()[0].webContents.send('on:system-download:progress', tasks)` —— 走 `on:` 前缀的现有事件约定，节流 300ms 一次。
- **关键点**：`item.updated` 事件里读取 `state`（`progressing`/`completed`/`interrupted`）映射到任务 `status`（`active`/`complete`/`error`）。

### 文件 2：`electron/services/webview/events.ts` —— 接入系统下载跟踪
修改 `fallbackToSystem`：
- `item.setSavePath(...)` 后调用 `systemDownloads.trackDownload(item)`，让任务进入跟踪队列。
- 这样系统下载器从「静默落盘」变为「后台跟踪」，进度通过事件推送到渲染进程。

### 文件 3：`electron/ipc/download.ts` —— 新增系统下载 IPC
- `download:listSystem` → 返回 `systemDownloads.getTasks()`
- `download:removeSystem` (gid) → 移除系统下载任务记录
- `download:clearSystem` → 清空系统下载记录

### 文件 4：`preload/index.ts` —— 暴露 API + 事件
- `download` 对象新增：`listSystem` / `removeSystem` / `clearSystem`
- 新增 `onDownloadProgress(handler)` → `ipcRenderer.on('on:system-download:progress', ...)`，返回 unsubscribe 函数（遵循 preload 现有 `update:download-progress` 的模式）。

### 文件 5：`src/stores/download.ts` —— store 统一两个来源
- 新增 `systemTasks: ref<DownloadTask[]>`
- 新增 `refreshSystemTasks()`（拉 `listSystem`）
- 新增事件订阅：`init()` 里 `api.download.onDownloadProgress(tasks => { systemTasks.value = tasks })`，实时接收进度推送。
- 修改 `allTasks` computed：合并 `activeTasks` + `waitingTasks` + `stoppedTasks`（aria2）+ `systemTasks`（系统下载器），让 DownloadsPage 与侧边栏都看到统一列表。
- 新增聚合 computed：`downloadSummary` —— `{ active: number, waiting: number, error: number, totalSpeed: number, totalProgress: number }` 供侧边栏使用。

### 文件 6（新建）：`src/components/sidebar/DownloadStatus.vue` —— 侧边栏组件
布局对齐 `MemoryInfo.vue` 的紧凑风格（`px-3` 内边距、`text-xs`、三色条）。

- `collapsed` 展开态：显示一行「下载 N · X.X MB/s」+ 百分比，下方一条进度条（绿色=进行中、灰色=待下载、红色=失败）。
- `collapsed` 折叠态：缩为一个下载图标 + 进行中数量角标。
- 数据来自 `useDownloadStore().downloadSummary`。
- 点击：emit 事件给 `Sidebar` → 跳转 `sessionbox://downloads`（用现有的 `tabStore.openInternalPage('downloads')`）。
- **空状态隐藏**：`downloadSummary.active + waiting + error === 0` 时 `v-if` 不渲染。

### 文件 7：`src/components/sidebar/Sidebar.vue` —— 插入组件
在 `<MemoryInfo>` 上方插入 `<DownloadStatus :collapsed="collapsed" @open-full="..." />`。

## 不在本次范围
- 不修改 aria2 任务轮询逻辑（DownloadsPage 已有 2s 轮询）。
- 不持久化系统下载任务（重启后清空，与 Electron DownloadItem 生命周期一致）。
- 不改变 `alwaysAsk`/`downloadDir` 已修复的逻辑。

## 风险与取舍
- 系统下载任务**不持久化**：app 重启后记录丢失（Electron `DownloadItem` 本身也无法续传，这是 Electron 限制）。
- `item.updated` 事件节流 300ms：平衡实时性与渲染进程负担。
- 聚合 `totalProgress` 用「各任务已完成字节之和 / 总字节之和」，多文件混合时是合理近似。
